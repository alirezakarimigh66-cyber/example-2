# Laravel Authentication System with Role-Based Access Control (RBAC)

## Objective
Implement a complete, secure, and maintainable authentication system for the Laravel application. The system must support user registration, login, logout, session management, and role-based access control, distinguishing between administrators (`admin`) and regular users (`user`).

### 1. Authentication Modal: Login and Registration

Implement login and registration inside a single, reusable modal component instead of separate login and registration pages.

**Modal Requirements:**
- Create one shared authentication modal that contains both Login and Register forms.
- Provide a clear and intuitive way to switch between Login and Register modes without closing the modal or navigating to another page.
- Use tabs, toggle buttons, or a similar UI pattern to switch between the two forms.
- Open the modal when users click the Login or Register buttons anywhere on the website.
- Keep the modal design consistent with the application's existing UI, styling system, and frontend architecture.
- Ensure the modal is responsive and works correctly on desktop, tablet, and mobile devices.
- Include a close button and support closing the modal by clicking outside it or pressing the Escape key, where appropriate.
- Prevent interaction with the background content while the modal is open.
- Manage focus correctly when opening and closing the modal, and provide appropriate accessibility attributes, keyboard navigation, and screen-reader labels.
- Display validation errors, authentication errors, loading indicators, and success messages clearly within the modal.
- Preserve entered form data when switching between Login and Register modes where appropriate, without carrying passwords into unrelated fields.
- Prevent duplicate submissions while a request is being processed.

**Login Form:**
- Email address.
- Password.
- Optional remember-me checkbox.
- Password visibility toggle.
- Forgot-password link if password reset functionality is implemented.
- Submit button.
- Link or toggle to switch to Register mode.

**Registration Form:**
- Name.
- Email address.
- Password.
- Password confirmation.
- Submit button.
- Link or toggle to switch to Login mode.
- Client-side convenience validation combined with mandatory server-side validation.
- No public role-selection field.

**Authentication Behavior:**
- Submit forms using the application's existing Laravel authentication architecture.
- Use the appropriate request mechanism for the current frontend stack, such as standard form submission, AJAX, Fetch, Axios, Livewire, or Inertia, depending on what the project already uses.
- If asynchronous requests are used, update the modal without unnecessary full-page reloads.
- Handle validation errors, invalid credentials, expired sessions, network errors, and server errors gracefully.
- Protect state-changing requests with Laravel CSRF protection.
- Ensure that passwords and authentication tokens are never exposed in URLs or insecure client-side storage.
- On successful authentication, close the modal and redirect the user to the correct destination based on their role.
- Administrators must be redirected to the admin dashboard, and regular users must be redirected to the user dashboard.
- On successful registration, either authenticate the newly registered user and redirect them appropriately or follow the application's existing email-verification workflow.
- If authentication fails, keep the modal open and display a clear error message.
- Prevent unauthorized users from accessing protected routes, regardless of whether the modal is visible.

**Reusable Component:**
- Implement the modal as a reusable component that can be triggered from multiple locations, including the main navigation, header, and other relevant sections.
- Avoid creating duplicate modal instances or duplicating authentication logic.
- Keep authentication logic in the appropriate Laravel controllers, services, routes, or existing authentication components.
- Keep frontend presentation separate from server-side authentication and authorization logic.

### 2. User Registration and Authentication Backend

Implement the backend functionality required by the authentication modal:
- User registration with name, email, and password.
- Login using email and password.
- Secure password hashing using Laravel's built-in authentication facilities.
- Server-side validation for all submitted fields.
- Clear validation messages and authentication error handling.
- Secure logout functionality that invalidates the session and regenerates the CSRF token as appropriate.
- Session regeneration after successful authentication to prevent session fixation.
- Protection against CSRF attacks, brute-force login attempts, and common authentication vulnerabilities.
- Appropriate handling of unauthenticated users attempting to access protected pages.
- Optional email verification and password reset functionality if supported by the application or required by its authentication architecture.

Use Laravel's built-in authentication mechanisms wherever practical.

### 3. Role-Based Access Control

Implement a role-based authorization system with at least two roles:

- `admin`: Access to administrative pages and authorized management features.
- `user`: Access to regular user pages and features.

Requirements:
- Store each user's role in the database.
- Retrieve roles from a trusted server-side source.
- Assign the `user` role by default during public registration.
- Never allow users to assign themselves the `admin` role through form inputs, request parameters, mass assignment, or other client-controlled data.
- Prevent regular users from modifying their own roles.
- Provide a secure method for creating the initial administrator account, such as a database seeder or protected administrative setup command.
- Centralize role checks and authorization logic.

### 4. Middleware and Route Protection

Create or adapt the necessary middleware to enforce role-based access control.

Requirements:
- All administrative routes must require authentication and the `admin` role.
- User-specific routes must require authentication and the appropriate permissions.
- Guests must be handled appropriately when attempting to access protected pages.
- Unauthenticated requests must be redirected to the appropriate entry point or handled according to the application's architecture.
- Authenticated users without the required permissions must receive an appropriate `403 Forbidden` response or a safe redirect.
- Enforce authorization on the server, not merely by hiding navigation links or buttons.
- Protect sensitive controller actions and resources against unauthorized access.
- Ensure users can access only resources they are authorized to view or modify.

Use Laravel middleware, Gates, Policies, or other appropriate built-in authorization features.

### 5. User and Admin Dashboards

**User Dashboard:**
- Accessible only to authenticated users with the `user` role, unless additional roles are explicitly required.
- Display relevant user information.
- Provide a logout option.
- Serve as the default destination for regular users after login.

**Admin Dashboard:**
- Accessible only to authenticated users with the `admin` role.
- Display relevant administrative information.
- Provide navigation to authorized management features.
- Prevent regular users from accessing the dashboard directly through its URL.

The authentication modal should be available on appropriate public pages and should not replace or interfere with protected dashboards.

### 6. Post-Authentication Redirection

Implement secure and predictable redirection:
- Administrators should be redirected to the admin dashboard.
- Regular users should be redirected to the user dashboard.
- Preserve intended redirect behavior where appropriate, provided the destination is validated.
- Prevent open redirect vulnerabilities.
- Ensure users cannot access dashboards belonging to other roles.

### 8. Security Requirements

Follow Laravel security best practices:
- Hash passwords securely.
- Validate all input on the server.
- Use CSRF protection for state-changing requests.
- Regenerate sessions after authentication.
- Invalidate sessions during logout.
- Apply login rate limiting.
- Prevent privilege escalation and unauthorized role modification.
- Enforce authorization on protected server-side operations.
- Avoid exposing credentials, session tokens, secrets, or sensitive authentication information.
- Use secure session and cookie settings appropriate to the deployment environment.
- Do not store plaintext passwords.
- Do not rely on frontend-only checks for security.
- Follow the principle of least privilege.

Use the testing framework already configured in the Laravel project.

## Final Acceptance Criteria

The implementation is complete only when Login and Register are available through a single reusable modal, users can switch between forms without navigating to separate authentication pages, successful authentication redirects users according to their database-defined roles, unauthorized access is blocked server-side, and the relevant tests pass.

Prioritize security, usability, accessibility, maintainability, and compatibility with the existing Laravel application.

- Replace the email field with a phone number input.
